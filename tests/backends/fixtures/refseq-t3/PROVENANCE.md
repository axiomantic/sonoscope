# Reference Sequencer T3 arbitrary-pattern QA goldens (pinned)

These 24 files (4 patterns × 6 files) are **pinned QA goldens** delivered to sonoscope over the
sonoscope↔Reference Sequencer MIDI-QA contract. They drive `tests/backends/test_midi_t3_integration.py`, which
loads each pattern into the real `ReferenceSequencer.clap` via CLAP `load_state`, drives the host transport, and
verifies the captured note-out equals the golden (and trips RED on three injected faults).

## Provenance

These fixtures are T3 arbitrary-pattern MIDI-QA goldens for the reference sequencer, delivered
over the sonoscope↔reference-sequencer MIDI-QA contract and consumed by
`tests/backends/test_midi_t3_integration.py`.

- **Generated by** the reference sequencer's OWN shipped codec + scheduler, run over each pattern's
  transport. Because the goldens are produced by running the real scheduler over each transport,
  `capture == golden` holds by construction (bounce == live; a round-to-nearest-sample fix makes
  emitted `t_samples` block-size invariant).
- **Plugin binary** these goldens target: `ReferenceSequencer.clap` inner Mach-O sha256
  `017c9d4f5575314c89e08e0ecffa6b8b4e998f877af61704d1ee093c42335516`.

Do NOT hand-edit these files; regenerate upstream and re-deliver via the contract.

## Files per pattern `<name>`

| File | What it is |
|------|-----------|
| `<name>.state.b64` | base64 of the SQBT v2 `clap.state` blob — CLAP `load_state` input (decode → raw bytes) |
| `<name>.transport.json` | driving transport (tempo_bpm, start_position_beats, duration_beats, tsig_num, tsig_den, sample_rate, block_size) |
| `<name>.correct.json` | the CORRECT expected-MIDI golden (event list) — capture must **PASS** against it |
| `<name>.broken-droppedoff.json` | `correct` with ONE `note_off` removed |
| `<name>.broken-wrongchannel.json` | `correct` with ONE event's `channel` changed |
| `<name>.broken-mistimed.json` | `correct` with ONE event's `t_samples` shifted +50 |

Event schema is sonoscope's S1 `MidiEvent`: six fields `{type, channel, note, velocity, t_ticks (@960
PPQ), t_samples}`, ascending by `t_samples`, `note_off` before `note_on` at a coincident sample. The
capture window is half-open `[start, start+duration)`.

## Tripwire classification note (broken variants)

The three `broken-*.json` are **wrong expected specs**: the real capture equals `correct.json`, so
comparing the capture against a broken spec yields a mismatch that proves the comparator catches that
fault class. How sonoscope's comparator (`evaluate_midi`) classifies each, verified live against the
`017c9d4f` build (see the test module docstring):

- `broken-wrongchannel` → **wrong-field** (`wrong_field` field == `channel`).
- `broken-mistimed` → **mistimed** (`delta_samples` magnitude 50 > the ±1 tolerance).
- `broken-droppedoff` → **missing-or-extra** (exactly one `extra` captured `note_off`), **not**
  `stuck-note`. The stuck-note firewall runs on the captured ground truth (which is correct and fully
  paired); a note-off dropped from the *expected* spec therefore surfaces as an extra captured
  note_off, not as an integrity/stuck-note violation. The upstream README labels this fault
  "stuck-note tripwire" after the fault's real-capture semantics; through the sonoscope
  capture-vs-expected path it is a `missing-or-extra` RED.
